# Updating the content

All content lives in `src/data/`. The 3D store, the 2D directory and the shopkeeper's knowledge are all generated from these files; after editing, run:

```bash
npm run check   # structure + bilingual + link validation, prints pending information
npm test        # shopkeeper/knowledge tests
npm run dev     # http://localhost:8080/
```

**Rules**: `null` = "not provided yet": the UI hides the field and the shopkeeper says it does not know. Never invent a year, figure, software, role or link. Provisional things are marked so they can be found and replaced.

## 1. Add a project

Append an object to `PROJECTS` in `src/data/projects.js`. Fields actually used today:

| Field | Type | Notes |
| --- | --- | --- |
| `id` | string, unique | Used by the scene, the 2D directory, AI actions (`[[project:<id>]]`). Never reuse. |
| `slug` | string, unique | URL-friendly name. |
| `year` | integer or `null` | Leave `null` if unknown (shown as "year to confirm" on the back of the sleeve; never displayed blank). |
| `categories` | string[] of `CATEGORIES` ids | **The first id decides which physical bin holds the record**; the others are tags (2D filter, knowledge). |
| `artwork` | 3 hex colours `[main, accent, dark]` | Palette for the generated sleeve and label. |
| `title`, `short` | `{ fr, en }` | Required in both languages (`npm run check` fails otherwise). |
| `context`, `challenge`, `role`, `outcome` | `{ fr, en }` or omitted | Printed on the back of the sleeve and in the liner notes. Omit a field rather than writing an empty string. |
| `work` | `{ fr: string[], en: string[] }` | Becomes the "tracklist" inside the sleeve. |
| `skills`, `skillsEn` | string[] | French / English skill chips. |
| `collaborators` | string[] | Names only for confirmed collaborators. |
| `visualStatus` | `"provisional"` or omitted | `"provisional"` prints "provisional artwork" on the back. |

Limits to know (checked in the code, not assumed):

- **A bin shows at most 3 featured records** (3 columns per bin, `src/scene/furniture.js` `buildGondola`). A 4th project whose first category is the same will exist in data, the 2D directory and the shopkeeper's knowledge, but **will not appear as a 3D record**. Give it a different first category or ask for the bin layout to be extended.
- The gondola has exactly **6 bins** (`categories.slice(0, 3)` front tier, `slice(3, 6)` rear tier). Categories beyond the sixth are not shown in 3D.
- The data model has **no `images`, `videos`, `documents` or `externalUrl` fields** yet, although the brief lists them. They are not read by the scene or the UI.

### Real cover art (not wired yet)

Final art is supplied through `project.cover.front` / `project.cover.back` (image URLs): `src/scene/records.js` loads `cover.front` into the sleeve front and `cover.back` into the back cover (`createRecord` / `ensureRecordDetail`); until a URL is set, the sleeve is generated by `drawProjectCover()` (one hand-written composition per project id in the `COVER` table, with a generic fallback) and flagged `provisional`. The loading path has been exercised only with generated art, not with a real image yet. Put image files under `assets/covers/` (square, ideally 1024 px, WebP/JPEG) and remember that images referenced from `index.html`/CSS/JS must be relative paths (GitHub Pages sub-path).

## 2. Remove a project

Delete its object from `PROJECTS`. The record disappears from its bin, the 2D directory and the knowledge base; `npm run check` verifies nothing else references it. If it was one of the featured records, the bin shows filler sleeves in that slot.

## 3. Add an application to the SOPP Agents rack

Append to `APPLICATIONS` in `src/data/applications.js`: `id`, `name`, `category {fr,en}`, `description {fr,en}`, `url` (http/https), `repository` (http/https). Do not describe features the app does not have.

The rack lays cases out in **4 columns × 2 rows = 8** (`buildAppsRack` in `src/scene/props.js` computes `rows = ceil(n / 4)`). With 9+ apps a third row is generated but the back board (2.45 m tall), the header sign and the ceiling were sized for two rows, so it would collide with the ceiling. **Up to 8 apps: data-only change. Beyond 8: ask for a layout change** (second rack or taller board). `npm run check` warns above 8.

## 4. Categories

Edit `CATEGORIES` in `src/data/projects.js` (`id`, `fr`, `en`). Keep exactly six for the 3D gondola. The short plate text printed on each bin comes from `TAB_LABELS` in `src/scene/furniture.js` (falls back to the category label if the id is not listed there); the large hanging sign uses the category label.

## 5. CV (PDF)

1. Put the file in `assets/cv/` (e.g. `assets/cv/Adam-Soppelsa-CV.pdf`).
2. In `src/data/profile.js` set `cv.url` to the **relative** path `"assets/cv/Adam-Soppelsa-CV.pdf"` and optionally `cv.updated`.
3. `npm run check` fails if the path does not exist. Until then the folder on the counter says the updated version is coming; no fake CV exists.

## 6. Email and links

In `src/data/profile.js`:
- `contact.email`: set to the confirmed address. The candidate address from the old portfolio is deliberately **not** in the repository until the owner confirms it.
- `contact.links[]`: set `url` (must be `https://…`) for `linkedin`, `instagram`, `spotify`, `youtube`; add entries `{ id, label, url }` for others. Links with `url: null` are hidden. GitHub is pre-filled (`https://github.com/sopp24`, derived from the verified app repositories).

## 7. Master 2 and availability

In `profile.status`: `degreeTitle`, `institution`, `availableFromDate` (ISO date). Today only "Master 2", "graduating soon", "available from September" and "open to international" are confirmed. `education[]` / `experience[]` entries have `confirmed: false`: they are shown (and spoken by the shopkeeper) as history "to be confirmed". After you validate one, set `confirmed: true` and fill missing fields (e.g. `institution`). The music figures (`music.historical`: 12 years, "13 millions") are likewise unconfirmed and are not presented as current facts.

Note: the two personal records on the About shelf ("Davis Miles", "STORY.") are defined in `MUSIC_PROJECTS` in `src/scene/world.js` (palette, short text) and mirrored by name in `profile.music.projects`. Edit both until they are unified.

## 8. Add a language

Not a data-only change. Touch, at minimum:
- `src/core/i18n.js`: add the UI strings for the new code and the language switch entry.
- Every data text object (`{ fr, en }`) gains a third key; `scripts/check.mjs` currently requires `fr` and `en` only.
- `src/scene/artwork.js` `LABELS` (liner-notes headings) and `src/scene/furniture.js` `TAB_LABELS`, plus the `draw(lang)` sign functions in `furniture.js`, `props.js`, `room.js` — several index `[lang]` with a French fallback, but `LABELS[lang]` has **no** fallback and would throw.
- `src/data/knowledge.js`, `worker/prompt.js` and `src/ai/local-faq.js` (language detection and canned sentences).
- `src/audio` is language-free.

## 9. Shopkeeper knowledge

It is **generated** by `src/data/knowledge.js` from `projects.js`, `applications.js` and `profile.js` — there is no separate file to edit. Unconfirmed facts are tagged `historical-unconfirmed`; missing ones are listed in `notProvided`. Behaviour rules live in `worker/prompt.js` (kept separate from the knowledge). After changing data run `npm test`; see `docs/BACKEND.md` for deployment.

## 10. Decorative artwork

The fictional bands, posters, stickers and filler covers are generated in `src/scene/artwork.js` (`DECOR_BANDS`, `DECOR_PALETTES`, `POSTER_DEFS`, `drawStickerAtlas`). They are scenery, **not deliverables**: two posters ("Winehouse", "STORY.") and their info cards are labelled as fictional décor. Edit those arrays to change the look.

## 11. Provisional vs final

| Item | State |
| --- | --- |
| Project sleeves, back covers, inner spreads | Generated, provisional (`visualStatus`). |
| Decorative covers, posters, stickers | Generated scenery, permanent unless you change it. |
| Davis Miles / STORY. sleeves | Generated placeholders; visuals and details to confirm. |
| App cases | Generated from name/category; no screenshots. |
| CV, email, social links, Master 2 title/institution/date | Pending (`PROFILE_PENDING`). |
| Project years (8 of 10) | `null` until provided. |
